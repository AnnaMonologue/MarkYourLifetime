# 纸上赶稿 v0.8｜交叉交互修复记录

基准：[v0.7 全交互审计](../../../docs/fandom-ddl-calendar/INTERACTION_AUDIT_v0.7_2026-11-15.md)。此文记录本版本的实际处理方式与测试情况，**不是所有可能操作组合的形式化证明**。

| 审计编号 | 原问题 | v0.8 处理 |
|---|---|---|
| X01 | 收货 DDL 已不可行时未完成的本人工作消失 | 逾期本人任务仍出现在「我的进度」，标示原定截止日、需重新安排，不伪造当日配额 |
| X02 | 删除制品遗留原计划快照 | 同步移除对应 `data.baselines[p.id]` |
| X03 | 画稿手工完成被删除日志错误清除 | 手工阶段确认日期与有效日志分配分别保存；只撤销被删除日志自身的贡献 |
| X04 | 改活动 DDL 直接重算，不展示影响 | 先列出关联制品的最晚寄出与内容齐备变化，再确认提交；原计划和实际完成历史不覆盖 |
| X05 | 已验收的外部节点从日历消失 | 按实际完成日期保留灰色历史节点，不再算作待催稿 |
| X06 | 未来日期可作为实际产出保存 | 禁止晚于今天的实绩日期 |
| X07 | 全部画稿阶段已完成，但缺实际日期 | 逐张完成使用日期表单，整阶段完成日由有效完成事件取最大值；不猜无日期历史 |
| X08 | 将运输挪至下印中间导致排程失败 | 禁止运输非法移动／删除／改为非物流工序；新普通下印工序插到运输前 |
| X09 | 删除图稿后留下悬空日志关联 | 在制品内部归档原图稿及受影响日志，移除当前有效日志中的无效图稿引用 |
| X10 | 在进度表单取消完成无效 | 恢复未完成时同步更新状态及有效完成日，记录恢复历史 |
| X11 | 编辑工序撤销完成保留旧 `completedAt` | 置空当前有效完成日，保留变更历史 |
| B18 | 超额字数无反馈 | 录入超过目标时明确询问，若确认则保留实际产出，不截断真实数据 |
| U01 | 在制品 A 打开管理流程，切换 B 仍是管理模式 | 切换制品重置管理与展开 UI 状态 |
| U02 | 本人工作出现不会生成提醒的“提前提醒”入口 | 本人任务不再展示此催稿按钮；工序设置隐藏该组配置 |

## 数据依据

- 每张图的 `manualPhases` 保存用户手工确认的阶段完成日期；进度日志保留其 `pieceIds`。展示状态与整阶段完成时间从两者的有效证据共同计算。
- 删除画稿时，相应历史记录归档在所属制品的 `archivedPieces` 和 `archivedPieceLogs`；这些记录不会再计入当前工作进度。
- 已完成工序保留对下游的依赖；计划基线和人工约定日期与最新预测分离。
- 旧版仅写入 `piece.sketch=true` 而无日期的布尔状态**不足以证明完成日期**，测试不能把它推定为今天。
