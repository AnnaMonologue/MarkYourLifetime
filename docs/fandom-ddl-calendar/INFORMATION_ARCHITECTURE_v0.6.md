# 纸上赶稿｜v0.6 信息架构与「我的进度」规则

日期：2026-11-15。状态：页面交互设计及 Alpha 实现记录，未替代产品逻辑总规范中的待审日期规则。

## 1. 产品边界（用户最新确认）
- **主催单人使用**：作者、画师仅是被主催记录的参与者。
- 本工具是一个辅助记忆和 DDL 可视化日历：不设计发送催稿消息、外部通知或手机推送，不把这些放进后续路线。
- 从零创建新项目；取消旧版本的数据迁移/导入。可选本地 JSON 导出用于自行备份。
- 保留文本、漫本、合志、图集、周边五种可编辑工序模板；不扩展经营管理、销售、库存。

## 2. 导航结构
桌面：主导航「赶稿日历 / 我的进度 / 我的制品 / 参展活动」。进入「我的制品」或「参展活动」后，紧邻主导航出现第二纵列，第二列列出具体制品或活动，右侧展示对应详情。切换第二列项目无需返回汇总首页。手机改成水平可滚动标签。

## 3. 赶稿日历：只负责全局可视化
单一月历/手机周历，统一展示：红色收货 DDL、蓝色外部交稿或下印节点、黄色节点提前提醒、绿色主催本人的每日创作任务。不再保留「全部 / 主催 / 我的」筛选器；不在日历上方塞催稿待办或下方重复显示当日任务。月历每格最多显示 3 项，更多使用 +N；点击日期弹出当日全部事项清单；再点具体事项进入相应记录界面。

## 4. 我的进度：单日操作中心
**今日赶稿**：只展示主催本人承担的任务，可按日期回看/补录。每张卡只保留制品、环节、当天目标、当天已记、累计进度、记录按钮；完成后变灰并按当前工作路线显示排序。可同时涵盖多件制品，但不将不同单位相加成错误总数量。

**今日记录**：按本日日志显示填写过的实际新增字数/P/张、阶段描述、手动输入用时。保存后留在「我的进度」，不跳回月历。允许一天多条记录。

**需要关注**：只供主催自己查看，包含提前提醒已触发但尚未处理、约定节点逾期、待验收、需返修等事项。过去日期的未处理提醒仍显示在这里。执行「已联系」只改变联系历史，不等于作品交付成功。

**未来 14 天**：按时间排序显示临近交稿/下印节点与收货 DDL，便于提前安排催稿，避免只看今天。与「需要关注」尽量去重；未来窗口仅是显示范围，不能改变硬性 DDL。

**按日期切换**：日常工作与今日记录按所选日期展示；「需要关注」「未来 14 天」始终基于实际今天，避免回看历史时把旧提醒误当成现在的事项。进入「我的进度」默认回到今天。

## 5. 排程与数据一致性
继续使用 P0 最晚允许日期/预计日期双向计算及 P1 交付状态；「完成」不删除依赖，原计划基线不随今天变化。主催自己的工作以实际产出与剩余数量计算；外部参与者只记录节点。创建新制品时显式设置寄出前预留天数；运输不是在签收日重复产生的蓝色节点。

## 6. 验收关注
已做浏览器测试：四类事项同时可见、月历溢出可展开、保存进度后不丢当前页、已联系但未交稿仍是未完成状态、两级导航、移动端入口、旧版导入入口不存在。仍待长期验证：真实大规模合志的日历信息密度、逐张稿件与日记日志一致性、工厂节假日、极端延期场景。
