# 纸上赶稿｜v0.7 交互重整与验收清单（实施前规范）

> 日期：2026-11-15  
> 对照版本：v0.6 Alpha（GitHub \`projects/fandom-ddl-calendar/v0.6-alpha/index.html\`）  
> 状态：**本文件是下一版的交互实施规格，尚未修改网页**。与 [产品逻辑总规范](PRODUCT_LOGIC_v1.0.md)、[v0.6 页面架构](INFORMATION_ARCHITECTURE_v0.6.md) 并存。以下新增规定覆盖 v0.6 中“不保留三个筛选器”的决定。  
> 标注：**【确认】**=主催已有明确要求；**【落实建议】**=为了消除歧义提出的具体实现，开发前以本版为暂定方案；**【现状缺陷】**=已在 v0.6 源码定位的问题。

## 0. 不改变的产品边界【确认】

1. 网站只有一名实际使用者：**主催本人**。其他作者/画师仅作为主催录入的姓名标签、作品内容和交付节点，不存在外部成员登录、权限、在线协作、消息发送。
2. 核心只是**同人制品 DDL 倒排日历 + 本人每日进度 + 提醒自己催稿**。不做销售、库存、经营管理、供应商管理，也**不做自动催稿消息、邮件或推送通知**。
3. **全新项目，直接从零录入**，不开发旧版本数据迁移/导入功能。可保留当前项目的 JSON 导出作为本地备份，但不得在产品中把旧版本兼容包装成卖点。
4. 五种制品模板：**文本 / 漫本 / 合志 / 图集 / 周边**。所有制品都允许多个参与内容及多个并行工作路线；由主催维护，工序可增、删、改时长/目标、调整依赖。
5. 主催本人记录**日期、今日进度、今日用时（可不填）、标记完成**；外部人员仅跟踪节点、约定日、提前提醒、联系/交付/验收/返修状态。**没有计时器**。
6. 一律保持清晰白底、短标签、低信息密度。不要添加“工作台”“主催视角”“例如巴拉巴啦”或每行重复的“负责人：…”说明。继续使用“下印环节”“最近进度”“预计工期”等已确定文案。

## 1. 全站信息架构【确认】

桌面左侧第一列固定四个入口：

- **赶稿日历**（一张日历，提供 全部 / 主催 / 我的 **筛选切换**）
- **我的进度**（只做每日操作和自己要处理的提醒）
- **我的制品**（出现第二列制品目录，右侧为当前制品详情）
- **参展活动**（出现第二列活动目录，右侧为当前活动详情）

进入“我的制品”“参展活动”后，**第一列不消失**，第二列列出相应所有条目（可切换），右侧详情无须返回列表。手机端使用顶部/横向可滚动的二级标签，主导航依旧可达。

【落实建议】全站顶部动作随页面改变，禁止冗余 CTA：在“参展活动”页只放一个“新建活动”，在“我的制品”页只放一个“新建制品”；其他页面可保留必要的新增入口，但同一种动作不得出现两次相邻按钮。

【现状缺陷】v0.6 \`appShell()\` 总是放一个“新建活动”按钮，在活动页面又将主按钮也设为“新建活动”，因此同一工具栏重复两个动作。需要改。

## 2. 赶稿日历：恢复筛选，仍只有一份日历数据【确认】

**同一个日历组件、同一套数据源**。上方恢复三个文本筛选按钮（不是三个页面）：

| 筛选 | 显示 | 不显示 |
|---|---|---|
| **全部**（默认） | 红色收货 DDL、蓝色外部交稿/下印/最晚寄出节点、黄色提前提醒、绿色主催每日赶稿任务 | 不额外复制一条同义的运输完成节点 |
| **主催** | 红色收货 DDL + 蓝色需要主催关注的交付/下印节点 + 黄色提前提醒 | 绿色个人每日赶稿任务 |
| **我的** | 绿色自己负责的每日任务及必要的历史进度 | 其他人的交付节点、黄色催稿提醒；红色活动 DDL 不重复混入 |

用户切换只改变**事件可见性**，绝不能修改原计划/当前预测、操作记录或提醒处理状态。可以在当前访问期间保留所选筛选；新打开网站默认“全部”。

【落实建议】底层为每个日历事件标记业务类别 \`deadline | organizer-node | reminder | mine | mine-history\`，复用 \`allCalendarEntries()\` 后按类别过滤；不得维护三套单独的日历计算器。v0.6 中已有但未被实际使用的 \`ui.calendarMode:'all'\` 可直接作为筛选状态，并将按钮接入事件分发处理。

月视图同一日期按**红 → 黄 → 蓝 → 绿**的优先级展示（注：这是建议展示优先级，不修改实际事件时间）；多于 3 项只显示前 2–3 条和“+N 项”。**N 应按当前筛选结果计算**，点“+N”后弹出的也是该筛选下该日期的完整事项，不得偷偷显示另一类任务。切换筛选时当前月份保持不变。

日期小格最少显示“制品简称 + 事件”，例：\`《星光》 · 收货 DDL\`、\`《合志》 · A 草稿提醒\`、\`《星光》 · 正文 3000 字\`。完整负责人与交稿情况只在点击后查看。节点颜色可根据原先可编辑的颜色设置显示，但默认语义仍为红/黄/蓝/绿，**不能仅靠颜色判断**。

## 3. “今天”按钮的处理【确认 + 现状缺陷】

**赶稿日历工具栏删除“今天”按钮。** 当前日已用高亮标出，月份可通过前后箭头切换。

v0.6 代码实际存在 \`data-action="today"\`，点击后只做 \`ui.month=parseDay(todayISO()); ui.selectedDate=todayISO(); render()\`。它仅在已经切到其他月份时有较明显效果；若就在当前月份，视觉上几乎不变，用户会认为“没反应”。因此按明确反馈**删除按钮及对应分支**，不要留下不可见的空控件。

“我的进度”日期回看仍允许返回今天，但只在所选日期不是今天时展示**“返回今天”**；当前已是今天时不显示这一按钮，不占位置。

【落实建议】日历上只保留 \`上一月 / 下一月\`（手机周视图时为 \`上一周 / 下一周\`）；手机月/周切换明确显示当前选择或使用清晰的“月 / 周”二段式，避免按钮文本指向的动作和实际切换方向相反。

## 4. 日历的每一种点击行为

1. 点击**日期数字**：打开该日完整事项列表；列表严格遵循当前“全部 / 主催 / 我的”筛选，并保留选中日期。
2. 点击**“+N 项”**：打开同一完整事项列表。关闭弹窗返回相同月份/筛选；不跳转“我的进度”。
3. 点击**红色 DDL**：显示对应制品名称、关联活动、收货方式、DDL、最晚寄出和最晚下印节点，并提供“查看制品/活动”入口；不得误当成催稿可勾选任务。
4. 点击**蓝色交稿/下印节点**：打开该节点详情，可看计划日/约定日/实际日、当前状态及必要的处理选项（已联系、待验收、返修、确认完成），外部节点不出现个人用时框。
5. 点击**黄色提醒**：直接到对应节点的“提醒/联系”详情。记录“已联系”只保存本人的记事，不自动发送信息、不把节点标完成。
6. 点击**绿色个人任务**：打开该日期该工序的轻量记录表单；保存后回到之前日历日期、之前筛选。
7. 任何弹窗必须有清晰关闭操作；手机点击区域足够大；新增/完成操作有可见反馈，禁止“点了不知发生了什么”。
8. 事件已完成时可灰显历史，详情仍能查看实际日期；该历史不能因为正向/逆向重算被删。

## 5. “我的进度”：一天一个操作中心【确认】

**这是独立页面，不再把“当天所有事项”复制到日历下面。**

建议按清晰顺序展示（可左右两栏，但手机必须纵向）：

### 5.1 今日赶稿（最主要，绿色）

- 默认显示今天本人**未完成**的任务卡，按制品/工序明确区分；卡上只有制品名、当前环节、**今日建议量**、**今日已记录量**、累计进度和**“记录进度”**。
- 点击打开轻量表单：日期（默认当前所选日期）、今日新增字数/P/张或阶段说明、今日用时（可空）、标记完成；允许过去日期补录和一天多次记录。
- 保存后仍停留在“我的进度”当前日期，数值立即更新；不要重置到别的页面。
- 已完成的工作变灰并收进当前日期任务列表末尾，**不在列表中间反复占空间**；但最近记录可查。
- 同一天涉及不同单位的多项任务各算各的，不生成错误的“字+张”总和。用时如填写可汇总，但不强制填写。

### 5.2 需要关注（黄色/异常）

- 只列主催自己需要处理的**交稿前提醒、交稿逾期、已提交待验收、需返修、临近下印风险**；一项只出现一个当前最需要做的动作。
- 显示“制品/参与内容、节点、日期、为什么要关注”，允许点开详情、记录已联系、标记验收和追加返修。
- 提前提醒默认 7 天，可在具体节点改成任意非负天数；到期未处理要持续出现在“需要关注”，不能一过日历日期便消失。
- 仅本人的辅助记忆，不生成消息，不提供“发送给画师”按钮。

### 5.3 未来节点（精简）

- 显示未来约 14 天内最重要的节点、最晚寄出和收货 DDL，按日期排序。
- 已经出现在“需要关注”的同一事项不再重复显示；默认最多显示少量条目，展开可看更多。
- 不复制自己的逐日赶稿列表，因为那已经出现在“今日赶稿”。

### 5.4 最近进度（可折叠）

- 仅展示本人已录入的实际产出与用时记录，支持查看、更正误录。
- 不能拿已完成日志再次叠加成新任务；数量型目标由唯一有效记录来源计算。

### 5.5 日期交互

“前一天 / 日期选择 / 后一天”切换的仅是**本人当天赶稿与该日记录**；“需要关注”和“未来节点”永远以现实今天计算，避免查看上月时误以为旧提醒是今天的催稿事项。所选日期不为今天时才显示“返回今天”。

## 6. 我的制品与参展活动：两级导航【确认】

### 6.1 我的制品

- 第一列主导航始终显示“纸上赶稿 / 赶稿日历 / 我的进度 / 我的制品 / 参展活动”。
- 第二列显示所有制品，点击直接在右侧切换详情，不重载/丢失未保存数据。新增制品后第二列立即出现并自动选中。
- 右侧详情默认只展示制品标题、关联活动、距离关键 DDL、各参与内容目前所在环节/状态，以及下印环节当前节点；长列表需折叠。
- 每条参与内容的名字可编辑，例如“文本内容-作者A”；参与者姓名可修改；“我的工作”明确可选，自己与外部使用不同录入表单。
- 仅展开时显示大纲/正文/草稿/上色/细化等详细环节；增删环节、调整工期、目标数量、节点提前提醒等集中于“管理流程”，不在每条记录下放五六个按钮。
- 已完成工序灰显且排列到**所属内容的末尾**，但原始截止日和实际历史依赖仍保留。

### 6.2 参展活动

- 第二列显示所有活动；点击活动后右侧展示活动名、收货类型、硬性 DDL、关联制品。
- 建立活动：名称 → 官仓收货/酒店收货 → **自己填写** DDL → 保存；提示文案固定为“建议最晚 DDL 为官仓关闭前一天 / 漫展布展日前一天。”
- 修改活动的 DDL 须先显示受影响的关联制品和关键日期，确认后再重算；**不能悄悄改变原基线与实际记录**。
- 不新增多余的经营信息字段。
- 页面顶栏最多一处“新建活动”，不能有两个同名按钮。

## 7. 五类模板必须支持的录入方式【确认】

| 模板 | 默认创作内容 | 典型日常记录（本人）/ 典型节点（外部） |
|---|---|---|
| 文本 | 字数、大纲、正文；封设约稿、美工、校对可并行 | 新写字数 / 大纲交付、正文交付、封面定稿 |
| 漫本 | 预估 P、脚本、分镜、漫画正稿、封面 | 今天完成的 P/阶段 / 分镜验收、正稿交稿 |
| 合志 | 参与者人数，逐位选择文本/画稿，独立内容栏 | 自己承担的文本/绘图任务 / 每位作者或画师约定节点 |
| 图集 | 预计 P 与独立画稿张数，逐张草稿/上色/细化 | 逐张当前阶段的实际进度 / 草稿、成图交付 |
| 周边 | 约稿/自绘、草稿/上色/细化、拼车等待（可选） | 自绘记录 / 约稿、印厂对接、拼车节点 |

各类型共用“印厂对接 → 打样 → 大货 → 最晚寄出 → 收货 DDL”相关依赖，流程可编辑。画稿张数与印刷页数不可机械当成一回事。

## 8. 日期、提醒、状态的业务底线（交互不得破坏）

- 用户录入的收货 DDL 和已承诺交稿日不能被系统自动更改；自动推算的最晚日期、每日建议量可更新，但需与原计划、实际日期分离。
- **已完成不等于在算法中删掉工序**。实际寄出后，不得把大货结束日移动到签收当日。
- 工序并行时各自计算；下印环节等必要文件全部齐备，才满足汇合要求。
- 运输只用于推算最晚寄出，不在收货日另出一个同义蓝节点；可见/可编辑的寄出前缓冲，不做隐性减一天。
- 外部“已联系、已交稿、已验收、需返修”相互独立；返修保留先前记录并新增后续工作。
- 当前工期不可行时显示风险，不生成虚假合理的计划；预估工期未填充分时标注不确定。
- 不向外部人员自动发送信息；任何催稿完成操作只改变本地备忘数据。

## 10. 不实施的内容（再次明确）

不做任何在线协作账号、向画师发消息、推送通知、自动催稿、旧版数据迁移/导入、计时器、经营记录、库存、销售、财务模块。本次只调整主催自己看的交互，不能在下一轮扩张功能范围。
