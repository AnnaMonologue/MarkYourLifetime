# 纸上赶稿 · P0 排程实验

这里是独立的 JavaScript 排程引擎与旧版数据只读检查工具。**尚未替换 v0.3.1 正式日历**，也没有自动修改用户历史记录。

## 文件

- [scheduler.js](scheduler.js)：纯函数排程核心，按本地自然日语义进行日期运算；有向无环依赖、从收货 DDL 倒排最晚允许日、从实际与预计工期正推完成日、风险诊断、数量精确分摊。
- [legacy_adapter.js](legacy_adapter.js)：读取 v0.3.1 的五种制品数据结构，转为 P0 依赖图；不修改原始 JSON，不为没有日期的历史状态编造日期。
- [tests.js](tests.js)：Node.js 自动检查，**33/33 通过**。执行：`node tests.js`（建议 Node.js 18+）。
- [P0_排程只读检查.html](P0_%E6%8E%92%E7%A8%8B%E5%8F%AA%E8%AF%BB%E6%A3%80%E6%9F%A5.html)：离线网页诊断工具。打开后可使用示例数据，或导入自己从旧版导出的 JSON 备份。**只在浏览器内读取，不会上传、自动导入或保存数据**。

## 已验证

1. 收货 DDL 2026-12-30、物流 3 天、显式交接缓冲 1 天、大货 7 天：最晚寄出 12-27，最晚大货 12-20 开始、12-26 结束。
2. 已完成工序仍保留依赖和历史日期；不会由于标记「运输完成」就把大货推至收货当天。
3. 正文/封面可并行，汇合点必须等待全部前置路线完成。
4. 外部人员承诺交稿日与最晚必要日期独立保存并提示矛盾。
5. 旧完成状态缺乏实际完成日时保持未知，受影响后续预测标记不可确定。
6. 纯数量分配保证总和守恒，支持 0.5P。
7. 使用旧版实际 `mkTemplate()` 检查 **文本、漫本、合志、图集、周边 5/5 模板**，均可解析为新图结构。
8. 只读诊断页使用 Chromium 加载演示数据，并核对关键日期。

## 当前限制

- 旧版数量任务没有稳定的预计工期；适配器以 1 天作**技术占位**，并明确标记为不可靠。其影响的上游最晚日期也标成「暂定」，不能直接当作可执行赶稿计划。
- 旧版隐含的一天交接缓冲暂作为兼容假设，待新页面做成显式可编辑设置。
- 原计划基线存档、承诺交稿与实际日期的正式录入、跨制品每日负载、逐张图稿的唯一进度事件、提醒持续状态及旧 JSON 安全迁移**尚未接入正式网页**。
- 当前测试属于独立 JS 单元与兼容性验证，**不代表产品规范列出的 15 项端到端验收已完成**。

## 下一阶段
