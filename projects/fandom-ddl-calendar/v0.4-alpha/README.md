# 纸上赶稿 · v0.4 alpha（P0 集成验证版）

日期：2026-11-15。状态：**实验版，尚未完成正式迁移/端到端验收**。

本目录属于 `MarkYourLifetime` 仓库中的**独立子项目**；不会覆盖原有项目、根目录 README 或 v0.3.1。主页还是主催单人使用的「全部 / 主催 / 我的」日历，不引入协作账号、经营管理、销售或库存。

## 打开方式

- `index.html` 是**单文件可打开**的网页，P0 的 `scheduler.js`、`legacy_adapter.js` 和 `bridge.js` 已内嵌，不需要网络或服务器。
- **使用新的浏览器数据存储键** `zhishang-fandom-ddl-v04-alpha`，不会自动访问或改写 v0.3.1 的 `zhishang-fandom-ddl-v1`。
- 如需验证旧备份，可先在 v0.3.1 导出 JSON，再到 v0.4 的「备份 / 恢复数据」手动导入。导入前建议先另存原备份；备份属于本地存储且无云同步。

## 本轮实现（P0）

- 独立 `P0` 引擎替换 v0.3.1 中的 `scheduleProduct()` 倒排计算，保留依赖关系和已完成实际日期；运输产生「最晚寄出」，收货 DDL 不重复产生蓝色运输节点。
- 新增原计划基线：在制品详情点击「确认原计划」手动固定；更改 DDL 或进度不会悄悄重写原定计划。点击「重设原计划」需再次确认。
- 节点编辑允许录入「约定交稿日期」「人工确认的最晚日期」「实际完成日期」以及完成状态。未填写实际日期时保持未知，后续预测显示受阻，不自动填今天。
- 预估工期与真实工期分开；数量型环节新增「预计工期（天，可空）」。空白时按可用日期临时分配并提示风险，不宣称计算一定可执行。
- 已经关联的五种制品模板、三个日历视图和每日产出录入继续沿用原交互，代码仅在 P0 日期/状态层做必要接入。
- 已连接的约定交稿节点在「主催」日历使用人工约定日期；该日期晚于下印要求时，风险诊断会给出天数差异。

## 运行测试

- `node tests.js`：12 项 bridge 回归检查。
- `node ../p0/tests.js`：先前 33 项独立引擎检查（旧版 P0 目录）。
- 浏览器回归（本轮本地执行，含 5 模板、寄出后工期不漂移、原计划稳定、完成日期未知、页面无脚本错误）。测试环境禁止本地 HTTP 与 file 导航，因此使用浏览器 `set_content` 和隔离的测试用 localStorage 替身；不等于已在用户实际设备中验证存储持久化。

## 尚未解决（明确保留）

1. **数量型工期准确性**：无人工工期时只有临时日历分配。不同制品之间尚未限制主催个人产能，不能把预估产出当成保证。
2. **跨阶段的逐页/逐张进度和返修历史**：沿用旧结构，尚未统一事件日志，删除和更正日志仍需专项测试。
3. **提醒状态持久化**：目前提前 7 天只显示黄色提醒，没有“已联系/持续待处理”的完整状态机，也没有推送通知。
4. **工作日、节假日、实际物流时点**：依然按自然日；默认缓冲来自旧版设定，需要用户自行确认。
5. **完整旧数据迁移**：目前是新数据键+手动导入旧 JSON 的兼容方案，尚未完成版本化迁移、全部异常回滚和 15 项端到端验收。
6. **多路线任意依赖**：当前仍按路线内顺序串行、路线间并行、下印前汇合；后续需要在 UI 中开放更细的依赖编辑。
