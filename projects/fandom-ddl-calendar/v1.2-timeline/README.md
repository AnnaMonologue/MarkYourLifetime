# 纸上赶稿 · v1.2 — 横向交付时间线与参展资料提交

日期：2026-11-15。依据 v1.1 文人手稿界面继续扩展。该 HTML 是离线自包含应用，无需联网或安装。

## 本次改动

### 1. 制品概览：三阶段横向时间线

概览页取消原四块“制作路线/进度记录”跳转卡，改为按实际制作顺序横向展示：

1. **稿件交付**（青墨绿）：各制作路线的最晚交付日期，独立线路于此汇合。
2. **印厂制作**（冷蓝灰）：从印厂对接、打样到大货的当前预计最晚工期节点。
3. **邮寄计时**（赭朱红）：最晚寄出日期、运输预留天数及最终收货 DDL。

各阶段可查看节点日期，点击下方“查看相关环节”进入制作内容或下印流程。来源为现有 P0 排程数据，没有新增或修改计算规则；时间线展示的是**排程/最晚允许日期，不冒充实际完成日期**。长工序列表只在内部滚动，避免整个详情页无限增长。手机端改为纵向堆叠。

### 2. 参展活动：独立的“资料提交 DDL”

参展活动详情增加「资料提交 DDL」，可保存任意多条事项，例如：

- 申摊
- 摊位封面提交
- 摊位无料申请
- 街道福利申请

每条只需**事项名称和 DDL**。可自行标记已提交、撤销、编辑或删除。事件保存在所属活动的 `event.submissions` 数组中，**不属于制品，也不进入印厂/运输倒排图**。

在赶稿日历「全部 / 主催」中以紫灰色显示资料提交 DDL；「我的」筛选只显示个人赶稿，不混入这些外部/活动事项。点击日历条目可直接打开编辑弹窗；标记已提交后历史节点仍保留。到期未提交会出现在「我的进度 > 需要关注」，未来两周的未提交事项出现在「未来 14 天」。

参展活动修改收货 DDL 时，不自动更改资料提交项各自的 DDL。删除活动（且无关联制品）时，属于该活动的提交事项随活动一起移除，删除确认中会明确提示数量。

## 本版安全边界

仅主催本人本地记录。不发送申请资料、不发送消息、不推送通知；不添加登录、多人协作、经营/销售管理和旧版数据迁移。新版本使用独立的 `zhishang-fandom-ddl-v12-timeline` 本地存储，避免覆盖 v1.1。
