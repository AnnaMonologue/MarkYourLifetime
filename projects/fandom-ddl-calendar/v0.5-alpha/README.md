# 纸上赶稿 v0.5 Alpha — 催稿管理集成版

状态：测试版。用途是主催一人管理同人制品的收货 DDL、外部交稿节点、提醒、验收、返修与本人赶稿进度；不提供多人账号、销售和库存功能。

## 打开

打开 `index.html` 即可离线使用，计算模块已内嵌，不依赖网络。新版采用独立浏览器存储键 `zhishang-fandom-ddl-v05-alpha`，**不会自动覆盖 v0.4 或更早版本**。如需旧数据，从旧版导出 JSON，在新版「备份 / 恢复数据」中手动导入。导入会替换 v0.5 当前数据，请先备份。

## 本次新增

- 「主催」日历上方出现精简的「需要处理」区域，显示提醒日已过但仍未联系、交稿逾期、已提交待验收、需要催返修的节点；最多先显示四项，可展开其余。
- 交稿节点可记录 `等待交稿 → 已提交待验收 → 需修改 → 已确认完成`，并且**联系记录独立于交稿状态**。「已联系」不会把工作误设为完成。
- 每个节点可设独立交稿日期和提前提醒天数；默认提前 7 天。尚未处理的事项跨天持续可见。
- 主催可追加返修。未验收稿件新增返修轮次和约定日期；已验收稿件追加独立后续工序，保留原验收事实。
- 返修日期供 P0 预测使用，原先的约定交稿日期和历史提交事件保留。
- P0 的最晚寄出/收货 DDL、原计划基线、个人每日进度保持原逻辑。没有交付日期的旧记录保持“未知”。

## 测试

- `node followup_tests.js`：18/18 项独立催稿状态测试。
- `node tests.js`：12/12 项桥接回归测试（沿用 v0.4）。
- 原 P0 排程引擎：33/33 项测试通过（在此前 `projects/fandom-ddl-calendar/p0`）。
- 浏览器检查：联系→提交待验收→返修→确认完成→再次追加返修；主催收件箱显示；五种制品模板与 P0 日期不漂移；旧版 JSON 导入保存未知日期和基线。基于 Chromium 自动化的隔离页面环境完成，不等于在用户设备上验证过长期稳定运行。

## 仍需处理

1. 个人跨制品产能、逐页/逐张画稿进度与日志一体化。
2. 编辑/删除工序及纠正历史操作的完整撤销机制。
3. 完整的端到端验收、真实用户数据迁移和异常回滚。
4. 仅网页内提醒，不发送邮件/手机推送；无云同步。
5. 排程默认自然日，印厂节假日和具体物流揽件时点仍需人工核验；未录入稳定预计工期时日期属暂定。

## 目录

- `index.html`：单文件网页（可直接双击打开）。
- `scheduler.js`、`legacy_adapter.js`、`bridge.js`：P0 排程逻辑、旧数据只读适配与桥接。
- `followup.js`：本轮新增催稿、交付与返修状态模型。
- `tests.js`、`followup_tests.js`：自动化回归和 P1 逻辑测试。

原仓库 `MarkYourLifetime` 的旧项目与根目录 README 未修改。新内容全部放在 `projects/fandom-ddl-calendar/v0.5-alpha/`。
