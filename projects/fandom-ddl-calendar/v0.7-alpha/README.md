# 纸上赶稿 v0.7 Alpha — 日历筛选与交互修订

> 2026-11-15 · 独立测试版本 · 不覆盖 v0.6 与仓库原有项目。

下载并用浏览器打开 [index.html](index.html)。仅主催本人使用，所有外部作者和画师的节点由主催录入管理；无登录、外部消息、推送、旧版本导入、销售及库存模块。

## 本轮实现

- 一张赶稿日历，恢复 **全部 / 主催 / 我的** 三种筛选。全部=四类事项；主催=收货 DDL、交稿/下印与催稿提醒；我的=本人每日任务。筛选不改变数据和排程。
- 删除赶稿日历上没有明确反馈的「今天」按钮；保留上一月/下一月，手机端明确提供「周 / 月」切换。
- 日期数字和「+N 项」的弹窗仅展示当前筛选下的当天事项，数量随筛选改变。
- 红色 DDL 打开含制品、活动、交付方式、最晚寄出信息的详情；蓝色节点与黄色提醒进入交稿/联系状态；绿色任务进入每日进度录入。
- 「我的进度」保留手动填写今日产出及用时、需要关注和未来14天；非今天日期才出现「返回今天」；最近进度在底部可折叠回看跨日记录。
- 制品/活动保持两级导航，活动顶部重复的新建按钮已去除；仍保留 P0 日期计算及 P1 联系/验收/返修逻辑。

## 验证与限制

使用 Chromium/Playwright 在桌面 1350、1440 像素和手机 390 像素视口检查筛选、日期弹窗、颜色对应的点击动作、进度记录、二级导航、手机周/月切换和超出条目计数，测试通过。**此处属于交互回归；不是全部真实生产工期或节假日排程的验收。**

独立 HTML 保存数据至浏览器本地 `zhishang-fandom-ddl-v07-new`；从零录入，不提供旧版本数据迁移或导入。可导出当前版 JSON 备份。网页内提醒不会向任何人发送消息或触发系统推送。

产品讨论与 21 项交互测试标准：[v0.7 交互重整文档](../../../docs/fandom-ddl-calendar/INTERACTION_REDESIGN_v0.7_PLAN.md)。
